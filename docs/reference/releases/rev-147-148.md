## Supported features

* Automated deployment on Kubernetes and VM
  * [Terraform charm module](https://github.com/canonical/valkey-operator/blob/9/edge/terraform/charm/README.md)
  * [Terraform product module K8s](https://github.com/canonical/valkey-operator/blob/9/edge/terraform/product/k8s/README.md)
  * [Terraform product module VM](https://github.com/canonical/valkey-operator/blob/9/edge/terraform/product/vm/README.md)
* [Scaling a deployment up and down](/how-to/scale-horizontally)
* High Availability and automated rolling restarts
* Authentication and authorization by default
  * [Automated user and permission management for client applications](/how-to/clients)
  * [Password-less authentication via client certificates](how-to-clients-password-less)
  * [mTLS authentication](how-to-clients-mtls)
  * [Support for LDAP](/how-to/ldap)
* [Backup and restore](/how-to/back-up-and-restore)
  * Integration with any AWS S3-compatible, Azure or Google (GCS) object storage
* Security by design
  * Peer TLS encryption by default 
  * Optional [client TLS encryption](/how-to/tls)
  * Automated TLS certificate and CA rotation
  * Root-less mode in K8s deployments
* [Support for client relations](/how-to/clients) 
* Monitoring and logging
  * [Observability with Canonical Observability Stack (COS)](/how-to/monitoring)
  * Log file rotation
* Support for persistent storage
  * [Multiple persistence modes](/how-to/persistence)
  * Separate storage volumes for the database, logs and backup files
* [Juju user secrets for charm internal passwords](/how-to/manage-passwords)
* [Minor version upgrades without downtime](/how-to/upgrade)
* [Comprehensive Charm statuses](tutorial-charm-statuses)

## Requirements and compatibility

* Juju v3.6.29+
  * Older minor versions of Juju 3 may be compatible, but are not officially supported.
* Relation interface `valkey_client`
  * support for `data-interfaces` v1
  * backward compatibility for `data-interfaces` v0
* Integration with a TLS provider charm
  * `tls-certificates` interface v4
  * `certificate_transfer` interface v1
* Dual-substrate compatibility: The same charm can be deployed on Kubernetes and machine substrates
